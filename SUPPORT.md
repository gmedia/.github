# Support

This page explains where to send what. Picking the right channel is the fastest
way to get an answer.

GitHub is where GMEDIA develops and shares **public engineering projects**. It is
not a channel for GMEDIA customer or service support.

## Bug in a GMEDIA project

Open an issue in that project's own repository, not here. Include reproduction
steps, what you expected, and what actually happened.

Before opening one, search the existing issues — the answer is often already
there.

## Question about using a project

Check the project's `README` and documentation first. If the repository has
GitHub Discussions enabled, ask there. Otherwise open an issue and describe what
you are trying to do.

Please keep questions in the repository they concern. Questions filed against
unrelated projects tend to go unanswered.

## Feature idea or change proposal

Open an issue in the relevant repository describing the problem you are trying
to solve. Start with the problem rather than a specific implementation — it
leads to better discussion.

For substantial changes, open the issue before writing the implementation.

## Security vulnerability

**Do not open a public issue.** Follow the process in
[SECURITY.md](SECURITY.md).

## GMEDIA services and commercial support

Questions about GMEDIA's connectivity, infrastructure, or commercial services —
including billing, service status, contracts, and customer support — are not
handled through GitHub.

Use the official channels at **<https://gmedia.id/contact>**.

Issues opened on GitHub for commercial service matters will be closed with a
pointer back to this page.

## Response expectations

These are public projects maintained alongside other work. Issues and pull
requests are reviewed as maintainer time allows, and we do not offer a response
time guarantee on GitHub. Clear, reproducible reports get handled faster.
